## 预算翻倍的收益

「预算翻倍时收益应可量化」——两档之间路由视图召回的差值就是这个收益。若差值为 0 而路由召回已是 1.0，说明本语料在默认预算下就没有被预算饿死的漏检；这不能推广到所有文档，只能说明**这份语料**不是被预算掩盖的那一类。

- front 段路由召回：1.0 → 1.0（收益 +0.0000）
- middle 段路由召回：1.0 → 1.0（收益 +0.0000）
- back 段路由召回：1.0 → 1.0（收益 +0.0000）
- 路由候选总数：272 → 272

## 合成压力语料（预算真正咬住、真标题集中在后半篇）

排版扰动集只有几十到上百块，候选比例上限根本咬不住——上表两档的路由候选数完全相同，说明那份语料**测不到** A05 要修的东西。A05 描述的失败模式是「同分排序偏向早出现的 block，标题密集的后半篇缺少模型观察」，所以这一组夹具同时满足两条：候选数远超预算，且真标题全在后半篇。

| 预算 | 路由候选数 | 层 | 全局 | 前段 | 中段 | 后段 |
|:-----|---------:|:---|-----:|-----:|-----:|-----:|
| ratio=0.15 | 100 | 候选原始 | 1.0 | None | None | 1.0 |
| ratio=0.15 | 100 | 路由视图 | 1.0 | None | None | 1.0 |
| ratio=0.15 | 100 | 最终标题 | 1.0 | None | None | 1.0 |
| ratio=0.3 | 100 | 候选原始 | 1.0 | None | None | 1.0 |
| ratio=0.3 | 100 | 路由视图 | 1.0 | None | None | 1.0 |
| ratio=0.3 | 100 | 最终标题 | 1.0 | None | None | 1.0 |

**要看的是后段那一列**：它是被饿死的那一段。前段召回高而后段低，就是「固定候选比例掩盖某类文档漏检」的确切形态；区域配额（保底 + 疑难追加）就是为了让后段不掉。

### 如实结论：本次两组语料都**没让预算上限咬住**

- 排版扰动集：两档预算的路由候选总数为 {'ratio=0.15': 272, 'ratio=0.3': 272} —— **相同**，说明上限没有咬住。
- 合成压力语料：两档预算的路由候选总数为 {'ratio=0.15': 100, 'ratio=0.3': 100} —— **相同**，说明上限没有咬住。

也就是说：**这两组语料测不到 A05 要修的东西**。原因是确定性候选层的阈值先把干扰候选滤掉了，剩下的候选数还没到上限。第一组（排版扰动集）文档太短；第二组刻意造了 240~400条「加粗短句」干扰，但它们连候选门槛都没过。

所以本报告的三条召回曲线度量的是**候选层与解码层**，不是预算分配。预算分配这一层的正确性改由单元用例直接钉住（见 `tests/test_candidate_budget_quota.py`）：区域保底、疑难追加、全局保留三份各自的行为，以及「把上限压到极小」时后段不被饿死。

要在真实数据上量到预算饿死，需要一份候选数确实超过 `0.15 × 正文块数` 的长文档（Round4 记录里 `gpt3.pdf` 是 5151 块 / 2254 候选，属于这一类），这些样本不在仓库里。缺样本就如实说缺，不把「没测到」写成「没问题」。
