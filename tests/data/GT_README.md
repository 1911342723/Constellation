# Ground truth

Evaluation ground truth lives in three places. This document is the
single statement of how each set is built and what it may be used for.

## Locations

| Location | Dataset | Provenance | Maintained by |
|---|---|---|---|
| `tests/data/long_docs/ground_truth/` | 12 long PDFs (research papers, one standards document) | see `gt_source` below | `python -m evaluation.repair_gt` (fully automatic) |
| `tests/data/no_style/*.json` | 4 zero-typography synthetic PDFs | emitted with the PDFs | `python scripts/manual/create_no_style_docs.py` |
| `evaluation/ground_truth/` | DOCX benchmark set (`ibm_*`, `nested_hell`, …) | physical-feature heuristics plus manual review | `python -m evaluation.generate_gt` (skips existing files) |

## The `gt_source` field

Every long-document ground-truth file records its provenance:

- **`pdf_embedded_toc`** — fuzzy-aligned to `block_id` from the PDF's
  embedded table of contents. Author-signed and independent of the system
  under test.
- **`pdf_embedded_toc + abstract_entry`** — as above, with an Abstract
  entry inserted idempotently by `repair_gt.py`. Tables of contents almost
  never list the abstract, but it is a real section that any parser should
  detect.
- **`manual_expert_reference`** — for documents with no embedded TOC
  (`bert`, `resnet`), reconstructed from the reference section structure,
  aligned to physical blocks, with manual overrides. **The reference
  structure was AI-drafted** (a paper's section list is public factual
  knowledge) **and physically verified, but not double annotated by a
  second human.** Spot-check before relying on it.

## Schema

```json
{
    "doc_title": "...",
    "doc_authors": "",
    "gt_source": "pdf_embedded_toc",
    "headings": [
        {"block_id": 21, "title": "1 Introduction", "level": 1}
    ]
}
```

`block_id = -1` means the heading genuinely exists but could not be
located in the block stream. **Never use `0` as the failure sentinel —
`0` is a valid block id.** Doing so silently produced F1 = 0.000 scores
until the collision was found; the attribution is in
`experiment_results/f1_zero_diagnosis.md`.

Matching discipline used by `evaluation/metrics.py`:
`|pred.block_id − gt.block_id| ≤ 3` **and** title Levenshtein similarity
`≥ 0.6`.

## Constraints

1. **Ground-truth `block_id` is coupled to the extractor.** Any
   behavioural change (line merging, header filtering, span joining)
   shifts block ids. After changing `PdfProvider` — or after downloading a
   PDF revision that differs from the reference copy — re-run
   `python -m evaluation.repair_gt` (automatic, roughly two minutes) or
   the whole ground-truth set is void. The two `manual_expert_reference`
   documents are realigned by `python scripts/manual/realign_manual_gt.py`
   instead, which aborts without writing if any entry fails to match.

   This includes the **PyMuPDF version**, which is why `requirements.txt`
   pins it exactly. Text extraction changed in 1.25: `bert.pdf` yields 907
   blocks on 1.24.14 and 727 on 1.25 or later. Upgrading without
   realigning drops candidate recall from 96.5% to 17.6% while every test
   still passes, because the tests use synthetic fixtures rather than the
   ground truth.
2. **Ground truth must never be generated by the system under test**
   (for instance by the candidate generator) — that is circular. Tables of
   contents, author reference structure, and manual annotation are the
   admissible sources.
3. After any automatic regeneration, run the ground-truth health audit
   (empty tables, `block_id < 0` counts, monotonicity). The report lands
   in `experiment_results/gt_repair_report.md`.
